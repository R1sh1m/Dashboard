# ESP-IDF / clangd Editor Setup (Ground Bridge)

This document explains how to configure a C/C++ editor (VS Code + clangd /
c-cpp-tools) for the ESP-IDF v6.1 `esp_receiver` target so IntelliSense does
not report spurious `pp_file_not_found` errors (e.g. `sys/features.h` not
found in `ground_bridge.c`).

## Root cause

`ground_bridge.c` includes `<stdio.h>`, which transitively includes the
newlib/picolibc header `sys/features.h`. clangd must know the xtensa-esp32
cross-toolchain include directory to find it. Without those paths, clangd
indexes nothing and flags every system header as missing.

This is an **editor/tooling issue only**. The real ESP-IDF build (Ninja) is
fine — `esp_receiver/build/esp_receiver.elf` and `.bin` are produced
successfully.

## Durable fix (do this once, then repeat after every clean build)

### 1. Build esp_receiver at least once

Use the MCP tool or Ninja directly so `esp_receiver/build/compile_commands.json`
is generated. That file contains the exact `-I` flags the real compiler used.

### 2. Mirror compile_commands.json to the workspace root

clangd auto-discovers `compile_commands.json` by walking up from the edited
file. Place a copy at the repo root so clangd picks up exact include paths
with no hardcoded machine-specific values.

From the `Dashboard` root, run:

```pwsh
pwsh -File Scripts/sync_compile_commands.ps1
```

This copies `esp_receiver/build/compile_commands.json` →
`Dashboard/compile_commands.json`. Re-run it after every `esp_build` / clean
rebuild (toolchain versions change the paths).

### 3. Reload the editor window

After the sync, run **Developer: Reload Window** in VS Code so clangd
re-reads `.clangd` and re-indexes `ground_bridge.c`. The `pp_file_not_found`
diagnostic should disappear.

## `.clangd` (workspace root)

`.clangd` supplements the compile database with the xtensa toolchain libc
include paths as a fallback:

```yaml
CompileFlags:
  Add:
    - -I<USER_HOME>/.espressif/tools/xtensa-esp-elf/esp-15.2.0_20251204/xtensa-esp-elf/xtensa-esp-elf/include
    - -I<USER_HOME>/.espressif/tools/xtensa-esp-elf/esp-15.2.0_20251204/xtensa-esp-elf/xtensa-esp-elf/sys-include
    - -IC:/esp/v6.1/esp-idf/components/esp_libc/platform_include
```

If `compile_commands.json` is present at the repo root, clangd prefers it and
these hardcoded paths become only a safety net.

## Files involved

- `.clangd` — clangd compile flags (fallback include paths)
- `Scripts/sync_compile_commands.ps1` — mirrors compile_commands.json to root
- `esp_receiver/build/compile_commands.json` — generated by the ESP-IDF build
- `compile_commands.json` (repo root) — synced copy for clangd auto-discovery
- `esp_receiver/main/ground_bridge.c` — the file that triggered the error

## Verification

After setup, open `esp_receiver/main/ground_bridge.c` in VS Code. The
`#include <stdio.h>` line at line 14 should show no diagnostic, and
`sys/features.h` should resolve (hover → go to definition).
